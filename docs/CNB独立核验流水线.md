# CNB 统计表独立核验流水线

核验入口为 `audit_pipeline.py`。先精确匹配项目已采集的 SQLite 历史库，再按优先级低频检索公开网站。采集、数据库构建、VPS 部署与这条流水线独立运行。原统计表只读，核验成果不提交 Git，也不部署到 VPS。

日常只需要：**推送代码 → CNB 自动连续核验 → 本地拉取 Excel**。已有成果自动恢复，不需要填写提交 SHA 或逐片点击按钮。

```bash
# 已准备好查询清单后，推送一次即启动完整核验
git push origin codex/standard-table-audit

# 本地拉取最新成果，自动合并原统计表并生成 Excel
bash scripts/pull_audit.sh
```

Excel 位于 `local_audit/verified/标准信息核验结果.xlsx`。运行中也能拉取阶段成果；工作簿顶部和运行摘要会区分“正在自动核验”“全表已处理”和“已暂停”。`git pull` 用于更新代码，`pull_audit.sh` 用于拉取核验成果。

| 原表总行数 | 2,139 |
| 精确匹配历史库（含明确前缀格式规范化） | 709 |

可进入联网检索的唯一标准号共 1,641 个。重复标准对应的不同文件行仍全部保留，但复用一次查询。未匹配不能推断为废止；旧标准、建设类标准、团体标准等可能超出现有历史库或备案网站覆盖范围。

原表中的 GBT、SYT、SHT 等明确的推荐标准前缀会规范为 GB/T、SY/T、SH/T 后精确匹配，保留原表写法并记录筛查说明。规则仅覆盖明确的固定前缀，不改年份、编号或分册号，不猜测 GBZ、企业标准等可能有歧义的前缀。

**历史库仅用于筛查。** 当前全量采集程序只按标准号新增，已有记录不会更新状态，因此数据库构建日期不等于每条记录的最新核验日期。输出明确区分“本地历史数据匹配（未联网）”“本地未匹配（待联网）”和有网页证据的核验结论。

## 本地准备

```bash
uv pip install --python .venv/bin/python -r requirements-audit.txt

# 全表离线筛查，并生成适合提交的最小查询清单；不访问标准网站
.venv/bin/python audit_pipeline.py prepare \
  /Users/northwang/Downloads/standard_code/标准信息统计表.xlsx \
  --output-dir local_audit/precheck

# 只做离线筛查
.venv/bin/python audit_pipeline.py precheck \
  /Users/northwang/Downloads/standard_code/标准信息统计表.xlsx \
  --output-dir local_audit/precheck

.venv/bin/python -m unittest discover -s tests -v
```

提交到 CNB 的 `audit_inputs/standards.csv` 仅包含标准类型、标准号、原表行号、调度优先级和筛查原因；不含原文件名、大小、备注、原有来源链接或原 Excel。`audit_inputs/manifest.json` 记录原表、查询清单与历史数据库的 SHA-256，防止输入或恢复进度错配。筛查原因用于安排查询顺序，不作为网页核验事实。

输入表或历史数据库更新后，需要重新执行 `prepare` 并提交新的查询清单和 manifest。旧输入的成果不能恢复到新输入。程序将表格中的任何文字都视为数据，不执行其中的指令。

## 云端执行

在分支 `codex/standard-table-audit` 上推送会启动核验首片。每片上传进度后，自动启动下一片，直到全部可检索标准都已经尝试处理。网页的“自动完成统计表核验”按钮也可一键开始或恢复整个流程。main 原有采集、构建与部署入口保留。

推送首片先快速处理 3 个标准以验证链路，随后自动切换为每片最多 50 个；这一过程不需要操作。

每片依次执行：安装轻量依赖 → 离线测试 → 自动恢复最近的匹配成果 → 历史库完整性校验及全表筛查 → 联网补缺 → 生成 Excel → 上传成果 → 自动启动下一片。流水线锁防止两片同时请求、覆盖进度。代码更新后也会自动查找同一分支最近 50 次提交上的匹配成果，原表、查询清单和历史库的哈希相同即可恢复；新输入会自动重新开始。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| AUDIT_BATCH_SIZE | 50 | 每片最多处理的唯一原始标准数，替代链需另外查询 |
| AUDIT_DELAY | 5 | 所有标准网站请求串行，间隔至少 5 秒 |
| AUDIT_MAX_REQUESTS | 250 | 包括检索、详情、替代链、重试和跳转的请求总上限 |
| AUDIT_BUDGET_SECONDS | 1800 | 联网阶段 30 分钟预算 |
| AUDIT_RETRY_FAILED | 0 | “重查失败记录”按钮开启，失败记录至多补重试一次，避免无限循环 |
| AUDIT_SOURCES | samr,national,industry,local | 按顺序补缺；可增加 csres 作为第三方备用 |

优先级依次考虑废止及替代链、本地来源冲突、未匹配、原表与历史库不一致、字段缺失、一般历史匹配。优先级数字是任务排序值，不代表数据置信度。

默认查询全国标准信息公共服务平台，核心字段和必要的替代关系齐全后停止重复查询；不足时查对应的国家全文公开系统、行业或地方备案平台。官方来源无法提供的字段留空，失败可见。工标网适配已提供，但本地连接失败尚不能确定是 IP 封禁，首片不依赖它。详细的来源、精确匹配和正向替代链规则见 [统计表本地核验](统计表本地核验.md)。

遇到 HTTP 403/429 时该站点暂停 24 小时；连续网络失败三次暂停 1 小时。暂停状态随成果包持久化，后续分片或构建节点不会重置该限制，其它可用来源继续核验。达到时间或请求上限会保存进度并自动进入下一片。全部官方站点不可用、一个分片无完整标准进展或超过 100 片时，保存部分 Excel 并暂停；附件上传失败也不启动下一片。不会绕过验证码或通过轮换 IP 反复冲击网站。

首批已处理 28 个唯一标准，均确认状态；随后国家全文公开系统返回 403。新版自动恢复这批成果，保留该站点的暂停状态，继续其它来源。**全表处理完成意味着每个可检索标准都已尝试，不代表每个标准都查到了结果。** 未查到、未覆盖、替代链缺失或冲突的记录仍保留明确说明。

## 续跑与下载

不需要手动续跑或填写 SHA。推送后，进度恢复和后续分片由程序完成；本地下载也自动找到同一输入的最新成果。

附件保存 **7 天**，每片更新。权限不足、下载失败或附件损坏时停止，不静默丢弃进度。首次没有同一输入的成果时从筛查开始；自动续跑若没有找到前片成果，则停止。平台强制终止或附件上传失败时需要查看构建日志，不能假定本片成果已经持久化。

正常只用这一条命令：

```bash
bash scripts/pull_audit.sh

# 原表移动了位置，才需要显式指定路径
bash scripts/pull_audit.sh /新的目录/标准信息统计表.xlsx
```

下载命令复用已配置的 CNB Git 凭证，不需要另外输入或保存令牌。它自动完成附件校验、解压、原表 SHA-256 检查与按行号合并。

本地输出 `local_audit/verified/标准信息核验结果.xlsx` 保留完整原表的所有列和重复文件记录，新增核验字段、现行版本及日期、来源和说明。工作簿有可筛选的“标准核验结果”“字段证据”“替代关系”三张表，日期为可排序的 Excel 日期；外部文本不会成为公式。长结构化记录保留在 JSONL，避免 Excel 单元格长度限制导致证据被截断。

CSV、JSONL、网页快照和历史数据库也随成果保留。字段证据包含 URL、采集时间、请求参数、SHA-256 及相对快照路径。云端 Excel 只包含最小清单与核验信息；本地下载后合并完整原表，补回文件名、大小和备注等原始列。

Python 核验命令退出码 0 表示本片正常结束或无待处理项，2 表示本片没有任何标准确认状态，1 表示输入、存储或映射错误。CNB 对退出码 2 保留待核查项并继续其它标准；输入或运行错误则停止。`运行摘要.json` 记录累计处理数、剩余数量、任务状态、暂停站点和停止原因。

CNB 临时附件用于交付和续跑；最终数据保存在本地 `local_audit/`。该目录已被 Git 忽略，既有 CSV 回写脚本也使用明确白名单。
